# LAST WORKOUT 卡

兩頁都有一張 `LAST WORKOUT`，回答一個原本要點開熱力圖才知道的問題：**上一次動是什麼時候、做了什麼**。

共通規則寫在這裡一次，兩頁各自的差異寫在自己那一節。分兩份寫遲早會分岔。

| | Monkey | Captain |
|---|---|---|
| 範圍 | 全頁**最近一個訓練日**，不分動作 | **選中動作**的最近一次，跟著 tab 走 |
| 形態 | cardio 一種（純重訓日退化顯示） | cardio 與 strength 兩種 |

兩頁都在 `TRAINING LOG` 卡裡、趨勢圖旁邊，版面位置見 `docs/page-layout.md`。

## 共通規則

### 資料層完全不動

schema 不變、不新增檔案或欄位。「最近一筆是哪一筆」「距今幾天」「配速」「跟上次差多少」全部是查詢與計算的結果，符合硬規則「推導得出的值不要存」。

### 距今天數：三段號誌

| 天數 | 顏色 |
|---|---|
| 0–7 | 綠 `--pos` |
| 8–14 | 橘（Monkey `--streak`／Captain `#ffb648`） |
| 15+ | 紅 `--neg` |

文案：0 天 `TODAY`、1 天 `YESTERDAY`、其餘 `N DAYS AGO`。

綠色刻意用 `--pos` 而不是各頁主色：主色在頁面上到處都是，拿它當狀態燈號會失去對比。

**Captain 頁的三段號誌不套 `--tab-c`**，維持綠橘紅。它講「多久沒練這個動作」，跟練哪個部位無關。

天數以本地時區的今天為準，與 quest、streak、熱力圖最右一格用同一個 `TODAY`。

### `▲▼`：跟上一次比，不是跟平均比

四個差值，各自判斷、各自上色。一綠一紅是正常的（例如重量持平但容量退步）。

| 差值 | 進步門檻 | 文案 | 持平文案 |
|---|---|---|---|
| 距離 | ±0.01 km | `▲ 2.15 km` | `same distance` |
| 配速 | ±1 秒 | `▲ 23 sec` | `same pace` |
| 重量 | ±0.01 | `▲ 2.5 kg` | `same weight` |
| 容量 | ±1 | `▲ 100 vol` | `same volume` |

`▲` 綠＝進步、`▼` 紅＝退步、持平 `--muted`。**配速差正值代表變快**（這次每公里少花幾秒）。

**文案不寫方向**：`faster` / `slower` 這類方向詞不寫，`+` / `-` 正負號也不寫。`▲▼` 與紅綠已經在
講方向，而每個差值就掛在它描述的那個數值底下，指涉不會歪。**單位要留**（`sec` 與主數值的
`MIN / KM` 不同，`vol` 也不等於 `VOLUME KG`），四個差值才讀得成同一套。

持平門檻是為了擋浮點殘渣，不是為了美化。

### 版面與字級

三個主數值各 `flex: 1 1 0` 撐滿卡片，數字起點對齊出一條隱形網格。其餘各列靠左 `gap` 排，跟當日詳情彈窗的 `.dcMeta` 同一套。只有主數值均分，是因為它們是主角，其他列拉開會讓層次變平。

**漲跌幅掛在它描述的那個主數值底下**（`5.02 KM` 下面是距離差、`9:58 MIN / KM` 下面是配速差），不自成一列。中間那個沒有差值的數值（`MIN` / `SETS`）底下就空著。差值是 `display: block`，inline 吃不到 `margin-top`。

**卡內不畫分隔線。** 這張卡扁平化之後上下已經各有一條（上面是 PR 榜的分界、下面是趨勢圖的分界），中間再一條就是三條等距橫線擠在一屏，讀起來像三個並列區塊，其實只是一張卡。下段（選配欄位／組數明細）改用加大的留白分段。

**桌機的窄欄就是基準字級，手機用既有的 `@media (max-width: 640px)` 放大回去。** 這張卡在桌機只有 300px 出頭，比彈窗還窄；桌機才是那個窄的情境，寫成基準比寫成例外少一層覆蓋。實際數值看 CSS，不抄在這裡。

破紀錄標籤跟在項目名後面，窄欄放不下時**允許換行**，不縮字也不截斷。

**不列 `note`**：彈窗裡看得到，卡片再列一次是同一句話說兩遍，而且長度不可控會把卡片撐開。

### 互動

整張卡可點，開既有的當日詳情彈窗 `openDayModal(date)`，不新寫彈窗。

兩頁掛法不同，各自沿用該頁既有做法：Monkey 的卡片只渲染一次，直接 `addEventListener`；Captain 的卡片每次切 tab 都重建，改掛 `data-date` 讓 body 那個既有的委派接手，自己綁會一直重複掛。

hover 時整圈用強調色亮起來（`outline`，不佔版面所以內容不位移）、`VIEW DETAIL ›` 加底線。

**兩頁都有同一個 TDZ 陷阱**：渲染時會用到 `escHtml` / `esc`，那是 `const`，在宣告之前呼叫會爆。Monkey 把渲染的**呼叫**延到宣告之後；Captain 的 `renderAll()` 在檔案中段就跑，所以把 `esc` 的**宣告**移到前面。

### 破紀錄標籤

剛好破紀錄時在項目名旁掛 `<icon> NEW PR`，判定直接取各頁既有的 `isNew`，不另算一套。

會與 PR 榜的 `NEW!` 指向同一件事，這是刻意的：PR 榜講「歷史最佳是多少」，這張卡講「你上一次就是那一次」。

## Monkey 頁

### 一天算一次訓練

**一個訓練日 = 一筆**。同一天多筆 session 或多筆 cardio 就合併：距離相加、時間相加、配速用合併後的總數算。跟 `streak`、`currentQuest`、`personalRecords` 共用 `buildDayRuns`，同一天在頁面上永遠只有一組數字。

`buildDayRuns` **只掃 cardio**，純重訓日（`cardio: []`）不在它的輸出裡。這張卡要涵蓋純重訓日，所以 `lastWorkout()` 另外掃 `sessions`，不能直接取它的最後一筆。

### `lastWorkout()` 與 `prevCardioDay()`

兩個都在 `<script id="metrics">` 區塊裡，回傳的欄位看程式碼，不抄在這裡。三條非顯而易見的規則：

- 沒有任何 session 時 `lastWorkout()` 回 `null`，整張卡不出現，趨勢圖自動撐滿那一排（與 `SLEEP` 一致）
- **選配欄位（`hr` / `maxhr` / `incline` / `res` / `kcal`）只在當日恰好一筆 cardio 時才填。** 兩筆以上時心率不能相加、坡度與阻力不能平均，硬湊的數字沒有意義
- `incline` 與 `res` 的 `0` 是有效實測值，判斷要用 `!= null`，不能用真假值
- `res`（`resistance_level`，健身車的阻力檔位）與 `incline`（跑步機的坡度檔位）是**兩個不同的欄位**，不共用一欄：兩者刻度與器材都不同，混在一起事後分不出來
- `prevCardioDay()` 跳過純重訓日：那些日子沒有距離與配速可比

不重複驗證殘缺資料。缺欄位的紀錄 `build_dashboard.js` 已經擋在入庫前。

### 長條圖拉高填滿

同排會被拉成等高，`LAST WORKOUT` 內容較多，趨勢圖底部會空一截。`#weeklyDist` 用 `display: flex; flex-direction: column`，`.bars` 從固定高度改成 `flex: 1` 配 `min-height`，長高填滿。

手機上兩張各自獨立、不再等高，`.bars` 回到固定高度。**`min-height` 要一起歸零**，否則桌機那個下限會把手機的值頂上去。

## Captain 頁

### 選中動作的最近一次

Captain 頁整體以**當前選中的動作**為脈絡，PR 榜、趨勢圖全都是該動作的，這張卡跟著同一個脈絡。同一天有多個 session 也不影響：每個動作各自找自己最近的一次。

### 兩種形態

| | cardio tab | strength tab |
|---|---|---|
| 主數值 | KM / MIN / MIN&nbsp;/&nbsp;KM（HIIT 是 KM&nbsp;/&nbsp;H） | MAX `<unit>` / SETS / VOLUME `<unit>` |
| `▲▼` | 距離差、配速差（HIIT 是衝刺速度差） | 重量差、容量差 |
| 底部 | BPM / MAX BPM / INCLINE / RESISTANCE / KCAL（有才顯示） | 組數明細，沿用彈窗的 `.dcSet` 藥丸 |

**單位跟著資料走**，`MAX KG` 這種標籤不能寫死（`Bench Press` 是 `lb`）。

**第三欄看資料決定**：有 `speed`（衝刺速度）就顯示 `KM / H`，沒有才顯示平均配速。
平均配速對間歇沒有意義——暖身收操越長越難看——判斷用欄位在不在，不比對動作名稱。
規則出自 `hiit-intervals.md`。

組數明細是重訓形態的重點：重訓真正想看的就是「上次推幾公斤幾下」，比一個平均值講得更細。

### 擴充既有函式，不新增平行的一套

`buildDayRuns(exercise)` 與 `strengthSessionStats(exercise)` 都已回傳依日期排序的陣列，**最後一筆就是最近一次、倒數第二筆就是上一次**。只補上缺的欄位（cardio 的心率／坡度／阻力／卡路里、strength 的 `sets`），不寫新函式。其他消費者不看這些欄位，不受影響。

### 兩個 tab 的寬度必須一致

cardio 分支是柱狀圖、strength 分支是折線圖，**兩者都用 `flex: 2.3`，`#lastWorkout` 用 `flex: 0.9`**，切 tab 時右卡不會跳寬度。用 flex 比例不用固定 px，視窗變窄還能等比縮放。

**折線圖的 `viewBox` 與卡片寬度是耦合的。** SVG 配 `width: 100%; height: auto` 會等比縮放，所以卡片變寬時高度與圖裡的字級會一起長大。改動 flex 比例或卡片內距時要一起檢查 `lineChart` 的 `viewBox`，否則兩張卡會一高一低、拉出一片空白。

### 顏色跟著 tab 走

所有數值用 `var(--tab-c, var(--accent))`，這是 Captain 頁的既有語彙（`.accent` 本來就這樣定義）。

**已知撞色**：`--c-shoulder` 跟三段號誌的「7 天內綠」是同一個色值，切到 Shoulder tab 時數值與距今天數同色。目前接受，兩者位置分開、語意不衝突。

### 沒有測試覆蓋

**Captain 頁的 metrics 無法像 Monkey 那樣抽出來測。** 它只有兩個 `<script>`（一個資料注入、一個整份 IIFE），沒有 `id="metrics"` 也沒有 export 到 window，`test_monkey_metrics.js` 的做法行不通。

這是既有缺口。要補得先把計算函式抽成有標記的區塊並 export，那是獨立的一件事。目前靠 headless 探針驗渲染結果。

## 驗收

跑 `validate` 那幾支（見 CLAUDE.md），再用 `docs/verification.md` 的 iframe 探針檢查下列**不變量**——刻意不寫死量測值，版面一改那些數字就過期：

- 兩頁桌機：趨勢圖與 LAST WORKOUT 等高（差 ≤ 5px），Monkey 的 `.bars` 有被拉高
- Captain 桌機：**每個 tab 的兩張卡寬度都相同**，切換不跳
- Captain 重訓 tab：主數值單位跟著資料（`Bench Press` 顯示 `LB`）
- 數值顏色等於該 tab 的 `--tab-c`
- 距今天數的顏色符合三段號誌
- **每個漲跌幅都在它描述的那個主數值格子裡**，且排在該格標籤的下方
- **卡片內部沒有分隔線**（`.dcSet` 藥丸自己的邊框不算）
- 點卡片開出**對應日期**的彈窗，cardio 與 strength 都要測，主控台無錯誤
- 手機（寬度見 `verification.md`）：`LAST WORKOUT` 排在趨勢圖之前、全寬、無橫向溢出

## 明確不做

- **不存任何推導值**，不新增 JSON 欄位
- **不列 `note`**，彈窗裡已經有
- **不做「跟前 N 次平均比」。** 那種近期狀態指標曾經存在過（`AVG PACE`／`AVG WEIGHT`），是明知代價後移除的，不換一種形式復活
- **不做連續休息天數的提醒文案**（例如「該動了」）。距今天數的顏色已經在講同一件事
- **不為了對稱而統一兩頁的範圍。** Monkey 是單一時間軸、Captain 是動作脈絡，這是兩頁本來的差異，不是不一致
