# Monkey 睡眠與用藥紀錄:設計

日期:2026-08-05

## 目標

記錄 Monkey 每晚有沒有吃助眠藥,以及那一晚睡得如何,累積成未來調整減藥計畫的依據。

系統只做兩件事:

1. **蓋章**。每晚一格,吃了就蓋上去
2. **點開看那晚的明細**。品質、躺床時數、早上昏沉

不做趨勢分析、不做計畫遵守度判定、不畫折線圖。減藥規劃高度可能變動,而且要看的是原始紀錄本身,不是從紀錄裡再算出來的結論。

## 背景:目前的減藥規劃

藥物為苯海拉明（Diphenhydramine），OTC 抗組織胺助眠成分,每次 1 顆,用途是助眠。

2026-08-05 當下的規劃是「做一休一」:2026-08-03、08-05、08-07、08-09 各一顆,之後停藥。

**這段只是背景,不是規格。** 計畫會隨睡眠狀況調整,可能延長、可能加回上一階、也可能提前收。任何程式邏輯、驗證規則、頁面文案都不得引用這幾個日期。計畫不進資料層,變更史交給 git 與對話紀錄。

## 資料模型

### 檔案佈局

```
data/Monkey/
  2026-08-01-f6ec59.json      訓練紀錄(不動)
  rewards/                    炸雞券(不動)
  sleep/
    2026-08-04.json           一晚一檔,檔名即日期
    2026-08-05.json
```

`sleep/` 是子資料夾。`build_dashboard.js` 掃訓練紀錄用的是非遞迴的 `readdirSync` 加 `.json` 副檔名過濾,子資料夾不會被誤當成訓練紀錄,理由與 `rewards/` 完全相同。

資料層只有事實,沒有計畫。

### 一晚一檔

`data/Monkey/sleep/YYYY-MM-DD.json`:

```json
{
  "date": "2026-08-05",
  "medication": { "taken": true },
  "bedtime": "23:10",
  "wake_time": "07:00",
  "quality": 3,
  "morning_grogginess": true,
  "night_wakes": 1,
  "note": null
}
```

| 欄位 | 必填 | 型別 | 說明 |
|---|---|---|---|
| `date` | ✓ | `YYYY-MM-DD` | 就寢那一天,須與檔名一致 |
| `medication.taken` | ✓ | boolean | 那一晚有沒有吃 |
| `bedtime` | ✓ | `HH:MM` | 上床時間 |
| `wake_time` | ✓ | `HH:MM` | 起床時間 |
| `quality` | ✓ | 1–5 整數 | 主觀睡眠品質 |
| `morning_grogginess` | ✓ | boolean | 早上起來有沒有昏沉 |
| `night_wakes` | | number ≥ 0 | 夜醒次數 |
| `note` | | string / null | 當晚發生了什麼 |

必填的六個都是躺下或起床當下就知道的事,沒有需要事後回想估算的欄位。

`medication.taken` **一律必填,沒有例外**。它是一秒鐘答得出來的事實。停藥很久以後每晚都寫 `false` 略嫌囉唆,但誠實且便宜,省略等於允許「這晚我不確定」混進資料裡。

必填欄位不得為 `null`。答不出來就停下來問使用者,不要猜、不要略過、不要先寫個 0 之後補。

### 日期語意

`date` 一律指**就寢那一天**。`2026-08-05.json` 記錄的是 8/5 晚上入睡、8/6 早上起床這一段。

凌晨才上床仍算前一天:`bedtime: "01:20"` 出現在 `2026-08-05.json` 裡,指的是 8/6 凌晨 1:20。

`wake_time` 小於或等於 `bedtime` 時,視為跨過午夜。

## 驗證規則

`build_dashboard.js` 遇到下列任一狀況印出問題並 `exit 1`,連帶讓 GitHub Actions 部署失敗。壞資料不能入庫,build 失敗是去修資料,不是繞過檢查。

| 狀況 | 理由 |
|---|---|
| 缺任一必填欄位,或必填欄位為 `null` | 與 cardio 缺 `distance_km` 同級 |
| `medication.taken` 不是 boolean | |
| `quality` 不是 1 到 5 的整數 | |
| `bedtime` 或 `wake_time` 不符 `HH:MM` | |
| `night_wakes` 存在但非數字或為負 | |
| 檔名日期與檔內 `date` 不一致 | 這種錯最難用肉眼抓 |
| `date` 晚於今天 | 未來的睡眠不存在,多半是打錯日期 |
| 檔名不是合法的 `YYYY-MM-DD.json` | |

**不驗證記錄有沒有漏。** 漏記是要被看見的事實,不是要被擋下的錯誤 —— 漏了兩晚就讓 build 掛掉,只會逼人去編假資料。缺漏在集章卡上就是一個空格,自己會說話。

## 推導指標

只有兩個,都由 `MonkeyMetrics` 現算,不落地。

| 指標 | 算法 |
|---|---|
| 躺床時數 | `wake_time − bedtime`,`wake_time ≤ bedtime` 時加 24 小時 |
| 章格 | 從第一筆紀錄那晚畫到昨晚,每晚一格,最多 14 格。狀態為「吃了」、「沒吃」、「沒記錄」 |

章格兩端都收斂:

- **今晚不佔格子。** 今晚的紀錄要明天早上醒來才填得完(躺床時數、品質、昏沉都得睡完才知道),放一格在那裡只會永遠是空的
- **開始記錄之前的日子也不畫。** 那時候還沒有這套東西,畫出來會長得跟漏記一模一樣

兩者是同一個道理:空格必須只代表「該記卻沒記」。混進「本來就不該有」的假空格,真正漏記的訊號就被稀釋掉了。範圍**之內**的空缺照樣顯示,那是真的漏記。

一筆紀錄都沒有、或只有今晚那筆時,章格是空的,整個 section 不渲染。

躺床時數是睡眠長度能拿到的最好近似。入睡花了多久沒有記錄,所以它一定略高於真正睡著的時數,**不要在頁面上稱它為睡眠時數**。

## 頁面

只動 `dashboard-monkey.html`,**不新增頁面**。

### 集章卡

放在 `activity` 卡之後,自成一張卡。標題 `SLEEP` 放在卡片裡,字級與 `ACTIVITY` 相同,兩張卡看起來是同一套。

```
┌────────────────────────────────────────────┐
│  SLEEP                                     │
│                                            │
│  💊  ▢  💊✕  💊  💊  ▢  💊  💊✕  ⟨💊⟩     │
│                                    昨晚    │
│                                            │
│  LAST NIGHT  TAKEN · ★★★☆☆ · IN BED 7h30   │
└────────────────────────────────────────────┘
```

- 一晚一格,由左到右,**最右是昨晚**
- 三種狀態:
  - **TAKEN** — 彩色膠囊,琥珀色邊框
  - **NOT TAKEN** — 同一顆膠囊調暗去彩度,右下角一個紅色 ✕ 角標。刻意用同一顆膠囊而不是別的圖案,因為它講的是同一件事的另一面
  - **NOT LOGGED** — 虛線空格,什麼都沒有
- 卡片底部一行講「目前選到的那一晚」:狀態 + 品質星等 + 躺床時數,並在最左標出是哪天(昨晚就寫 `LAST NIGHT`)
- 被選到的那格加一圈亮邊。滑鼠移到哪一格就選哪一格,亮邊與底部那行一起跟著走,並停在最後滑過的那格。預設選昨晚,手機沒有 hover 就一直是昨晚
- 格子不另外掛游標旁的 tooltip:日期與狀態底部那行已經在講
- 點任一格開彈窗
- 不畫圖例:三種格子本身已經夠直白,底部那行又會把選到的那晚講成文字
- 章格是空的(沒有已過去的紀錄)時,整張卡不渲染

「NOT TAKEN」與「NOT LOGGED」必須一眼分得開:一個是「有這回事,那晚沒吃」,一個是「不知道那晚怎樣」。前者是資料,後者是缺口。

手機上格子放不下時折成兩列,不縮小到點不到。

**頁面文字一律英文**,與 dashboard 其餘部分一致。中文只出現在資料的 `note` 欄位裡(那是使用者寫的內容,不翻譯)。

### 彈窗

沿用 dashboard 現成的 `dayModal`,不新增元件。

```
┌────────────────────────────┐
│ 8 / 5                    ✕ │
│ 2026 · WED NIGHT           │
│                            │
│ 💊 TAKEN                   │
│ ★★★☆☆      QUALITY        │
│ 7h50        IN BED         │
│ 23:10–07:00 BED–WAKE       │
│ GROGGY      MORNING        │
│ 1           NIGHT WAKES    │
└────────────────────────────┘
```

- `night_wakes` 與 `note` 有記才顯示,沒記就不佔位
- 點到沒有資料的格子,彈窗顯示 `NO RECORD` 並說明還可以補記
- 星期用英文三字母縮寫(`SUN`…`SAT`),`dashboard-captain.html` 的訓練彈窗也一併改成同一套,兩頁不要一邊中文一邊英文

## 記錄流程

**每天早上記一次。** 起床後一次把昨晚吃沒吃、睡得如何全部填完,章就蓋上去。資料永遠是完整的,不存在「只寫了一半」的中間狀態。

新增 `.claude/skills/log-sleep/SKILL.md`,形狀比照 `log-workout`:

1. 讀使用者的口語輸入(例:「昨晚 11 點睡,7 點起來,有點昏,有吃」)
2. 解析成欄位,含當晚吃沒吃
3. 用繁體中文列出解析結果請使用者確認,有疑慮處主動指出
4. **確認之後**才寫檔、重建頁面、commit、push

確認關卡是唯一的人工把關,不得跳過。使用者確認前不建立任何檔案、不 commit。

三個必須處理的細節:

- **日期歸屬**容易搞錯。確認訊息裡要明白寫出這筆屬於哪一晚(例「這筆記在 8/5 晚上」),避免早上記錄時記成當天日期
- **支援補記**。漏掉的晚上要能事後補。使用者說「補一下上週三」時,skill 要算出日期、確認、寫檔。補記與當天記錄走同一條路
- **缺欄位就問**。必填欄位一律不得猜測。使用者只講了睡眠沒講吃藥,就回頭問那晚吃了沒

skill 不管減藥計畫,資料層沒有那個東西。

## build 腳本改動

`scripts/build_dashboard.js`:

- 讀 `data/<人名>/sleep/*.json`
- 執行〈驗證規則〉一節的檢查
- 注入 `/*SLEEP_DATA_START*/` 到 `dashboard-monkey.html`
- 躺床時數與章格狀態的推導寫進 `<script id="metrics">` 的 `MonkeyMetrics`

Captain 沒有 `sleep/` 資料夾,整段跳過,`dashboard-captain.html` 完全不受影響。

與現有 `REWARDS_DATA` 相同的保護:若 `sleep/` 有資料但頁面找不到 `SLEEP_DATA` 標記區塊,`exit 1`,避免資料被無聲忽略。

`wallet-monkey.html` 不受影響,不需要複製睡眠資料過去。

## 部署與測試

**`.github/workflows/pages.yml` 不需要改動。** 沒有新頁面,而 `data/**` 與 `dashboard-monkey.html` 都已經在 `paths` 觸發清單裡。這是選彈窗而非獨立頁換來的。

`scripts/test_monkey_metrics.js` 補睡眠測試:

- 跨午夜的躺床時數,含 `wake_time` 等於 `bedtime` 的邊界
- 近 14 晚章格:狀態正確、含沒記錄的日子、資料不滿 14 晚時前面的格子是空的
- 最右一格是昨晚而不是今天,且今晚的檔案存在時也不會多長出一格

`CLAUDE.md` 更新檔案地圖與延伸文件列表。

## 明確不做

- **趨勢圖**。折線圖、時間軸、用藥密度曲線一律不做
- **吃藥晚與沒吃藥晚的統計對照**。要比較就自己點開來看
- **記錄完整度分數與連續記錄天數**。集章卡上的空格已經回答了這件事
- **計畫遵守度判定**。不存減藥計畫,不比對「該吃沒吃」
- **入睡花了幾分鐘**。躺著憑感覺猜出來的數字,誠實度可疑,而且它是必填欄位裡最容易讓人放棄記錄的一個。連帶放棄「實際睡眠時數」,改用躺床時數當近似
- 夜醒次數的圖表。`night_wakes` 只入庫,只在彈窗顯示
- 睡眠資料的裝置匯入。全部手動輸入
- 獨立的睡眠頁面
- Captain 的睡眠紀錄。目前只做 Monkey

## 醫療定位

本系統只做紀錄與呈現,不產生劑量建議,不判斷該不該調整計畫。

苯海拉明是 OTC 抗組織胺,不是苯二氮平或 Z-drug,沒有生理戒斷問題。主要議題是耐受性(連續使用約 3 到 7 天鎮靜效果明顯下降)與反彈性失眠(停藥後最初 2 到 3 晚較難入睡)。減藥節奏由開藥或提供建議的專業人員決定。

`morning_grogginess` 入庫的理由:早上昏沉是苯海拉明的典型副作用,它隨停藥消退本身就是有意義的觀察。
