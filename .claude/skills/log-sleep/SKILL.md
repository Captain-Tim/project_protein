# 記錄一晚睡眠

把使用者的口語輸入轉成 `data/Monkey/sleep/<date>.json`,重建 dashboard,commit 並 push。

**先確認,再寫檔。** 使用者確認之前不要建立任何檔案、不要 commit。這是唯一的人工關卡,不要跳過。

## 這是誰的紀錄?

**目前只有 Monkey 有睡眠紀錄。** 資料一律寫進 `data/Monkey/sleep/`,頁面是 `dashboard-monkey.html`。

使用者要記 Captain 的睡眠 → **停下來問**。那需要先在 `dashboard-captain.html` 加 SLEEP 標記區塊與集章卡,不是在這裡臨時加一個資料夾了事。

## 這一筆算哪一晚?

**`date` 一律是「就寢那一天」,不是起床那一天。**

早上記錄昨晚的睡眠,`date` 是**昨天**。這是最容易記錯的地方,確認訊息裡一定要把日期講白。

凌晨才上床也算前一天:「昨天凌晨一點多才睡」記在前一天,`bedtime` 寫 `01:20`。

## 流程

1. 讀使用者輸入,依 §解析規則 抽出欄位。
2. 有必填欄位問不出來 → **停下來問**,不要猜、不要填 0、不要「先記其他的之後補」。
3. 用繁體中文列出解析結果給使用者確認(格式見下)。有疑慮的地方主動指出。
4. 使用者確認或訂正後,才寫檔 → 重建 → commit → push。

### 確認訊息的格式

```
2026-08-05（三）晚上 · Monkey

💊 有吃
躺床  23:10 – 07:00（7h50）
品質  ★★★☆☆
早上  昏沉
夜醒  1 次

以上正確嗎?確認後我就寫入並更新 dashboard。
```

躺床時數是算給使用者對照用的,**不要寫進 JSON**(推導得出的值不存)。

## 欄位

`data/Monkey/sleep/YYYY-MM-DD.json`,檔名就是 `date`:

```json
{
  "date": "2026-08-05",
  "medication": { "taken": true },
  "bedtime": "23:10",
  "wake_time": "07:00",
  "quality": 3,
  "morning_grogginess": true,
  "night_wakes": 1,
  "note": null
}
```

| 欄位 | 必填 | 說明 |
|---|---|---|
| `date` | ✓ | `YYYY-MM-DD`,就寢那一天,**必須與檔名一致** |
| `medication.taken` | ✓ | `true` / `false`,那一晚有沒有吃助眠藥 |
| `bedtime` | ✓ | `HH:MM` 24 小時制,上床時間 |
| `wake_time` | ✓ | `HH:MM`,起床時間 |
| `quality` | ✓ | 1–5 整數,主觀睡眠品質 |
| `morning_grogginess` | ✓ | `true` / `false`,早上起來有沒有昏沉 |
| `night_wakes` | | 夜醒次數,≥ 0 的整數。沒提到就省略,不要填 0 |
| `note` | | 當晚發生了什麼,沒有就寫 `null` |

**六個必填一個都不能少,也不能是 `null`。** `build_dashboard.js` 會 exit 1 擋下來並讓部署失敗
——build 失敗是去修資料,不是繞過檢查。

**沒吃就寫 `{"taken": false}`,不要省略整個 `medication`。** 「那晚沒吃」跟「那晚沒記」是兩件事,
集章卡上長得不一樣。

## 解析規則

### 時間

- 「11 點睡」→ `bedtime: "23:10"` 這類要問清楚分鐘,或直接用整點 `"23:00"`,不要自己編一個 `"23:07"`
- 「大概 11 點多」→ 問一下大概幾分,或用 `"23:30"` 但要在確認訊息裡標明是估的
- 一律 24 小時制、補滿兩位數:`"07:00"` 不是 `"7:00"`

### 品質 1–5

使用者通常用口語。對照表:

| 口語 | `quality` |
|---|---|
| completely 睡不著、整晚翻來覆去、很糟 | 1 |
| 睡不好、淺眠、斷斷續續 | 2 |
| 普通、還好、就那樣 | 3 |
| 不錯、睡得還可以 | 4 |
| 很好、一覺到天亮、超好睡 | 5 |

拿不準就把你的判讀寫進確認訊息讓使用者改,不要自己決定完就寫檔。

### 早上昏沉

「起來有點昏」「頭很重」「爬不起來」→ `true`。
「很清爽」「精神不錯」→ `false`。
**完全沒提到 → 問**,這是必填,不能預設 `false`。

### 有沒有吃藥

使用者說「有吃」「吃了」→ `true`;「沒吃」「今天沒吃」→ `false`。

**沒提到就問。** 使用者只講睡眠沒講吃藥時,回頭問那晚吃了沒——不要從減藥計畫推。
計畫是計畫,吃沒吃是事實,這裡只記事實。

## 補記

漏掉的晚上要能事後補。使用者說「補一下上週三」「8/2 那晚忘了記」時:

1. 算出實際日期,**在確認訊息裡寫出完整日期與星期**,讓使用者確認沒算錯
2. 其餘流程完全一樣

檔案已經存在 → **停下來問**是要覆蓋還是使用者記錯日期了,不要直接蓋掉。

## 減藥計畫

**資料層沒有減藥計畫,這個 skill 也不管它。**

計畫隨睡眠狀況變動,存了就會跟實際脫節。使用者問「今晚該不該吃」→ 那是他跟醫囑之間的事,
這裡只負責把發生過的事記下來。

## 寫檔之後

```bash
node scripts/build_dashboard.js Monkey
node scripts/test_monkey_metrics.js
```

build 失敗就是資料有問題,回去修資料。測試失敗代表指標邏輯被動到了,不要繞過。

commit message 用繁體中文,格式比照現有紀錄:

```
chore(sleep): 記錄 2026-08-05 的睡眠
```
